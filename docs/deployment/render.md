# Render (website and backend)

**Status: Blueprint ready (`render.yaml`: `mckinley-site` + `mckinley-backend`); never deployed.**
Step-by-step: [../development/deploy-render-supabase.md](../development/deploy-render-supabase.md).

- Build: `pip install uv && uv sync --frozen --no-dev` (reproducible from `backend/uv.lock`).
- Start: `alembic upgrade head` then `uvicorn app.main:app --host 0.0.0.0 --port $PORT` (one process).
- Health: `GET /api/health` → `status`, provider/model, `is_mock`, `app_env`, database kind, resident source.
- `APP_ENV=hosted`: the app **refuses to start** with wildcard/localhost/http CORS origins, a missing or short
  `STAFF_API_TOKEN`, `GATE_OVERRIDE_ENABLED=true` or no `DATABASE_URL`. Messages never print values.

## The website (`mckinley-site`, a Render static site)
Builds the static export (`NEXT_STATIC_EXPORT=1 npm run build` in `frontend/`, publishes `out/`). Three **public**
settings are baked in at build time, so change one and redeploy the site: `NEXT_PUBLIC_API_BASE_URL` (the backend
address), `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. Never put a secret in a `NEXT_PUBLIC_*`
value. The Blueprint also sets basic security headers and makes `/staff` open the staff console. A build without the
Supabase settings (the here.now replay) shows no sign-in.

Limitations: the backend's free plan sleeps (first request ≈1 minute); the in-memory lock means one backend instance
only; staff and evaluation routes need a **staff sign-in** (invited staff, [../security/SUPABASE_AUTH.md](../security/SUPABASE_AUTH.md))
or the `X-Staff-Token` header (scripts); a hosted backend never treats "from this machine" as staff. Everyone else is a
guest, or an invited resident linked to one synthetic resident id.
