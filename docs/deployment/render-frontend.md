# Render (website, static site)

**Status (2026-11-11): deployed as a public demo, `https://mckinley-frontend.onrender.com` (free static site,
service `srv-dbqbpgrm8hqs73acc0f0`, branch `development`, auto-deploy on commit).** Prototype on synthetic data,
not production. The Vercel option (`frontend/vercel.json`, [vercel.md](vercel.md)) still works; use one website
host per backend.

## What it is
The Next.js app built as a **static export** (`NEXT_STATIC_EXPORT=1` → `output: "export"`, `trailingSlash: true`,
files in `frontend/out/`). No server code runs on Render for the website: the browser downloads HTML/JS and calls
the backend directly. It holds **no secrets**.

| Setting | Value |
| --- | --- |
| Type | Static site (Blueprint: `type: web`, `runtime: static`) |
| Root directory | `frontend` (the live service was created with the repo root and `cd frontend && …`; same result) |
| Build command | `npm ci && NEXT_STATIC_EXPORT=1 npm run build` (the variable must reach the **build** step, not only `npm ci`) |
| Publish directory | `out` (`frontend/out` from the repo root) |
| Plan | free (static sites are free on Render; served from a CDN) |

| Variable | Value | Secret? |
| --- | --- | --- |
| `NEXT_PUBLIC_API_BASE_URL` | `https://mckinley-backend.onrender.com` (the backend's https address) | **no**: built into the public JavaScript |
| `NEXT_STATIC_EXPORT` | `1` | no |
| `NODE_VERSION` | `22` | no |

`NEXT_PUBLIC_*` values are read **at build time**: after changing the backend address, redeploy the website. Never
put a model key, a database URL, a Supabase key or the staff token in a `NEXT_PUBLIC_*` variable.

## Routes and headers
- `/` customer chat, `/staff/` staff console (exported as `staff/index.html`; `/staff` also loads), unknown paths get
  the exported 404 page.
- `render.yaml` adds `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy` and a `/staff` → `/staff/`
  redirect. **The live service was created with the Render MCP tool, which cannot set headers**, so until the
  Blueprint syncs it these headers are missing (Render already sends `X-Content-Type-Options: nosniff` and HSTS).
  To fix by hand: Dashboard → the static site → Redirects/Rewrites and Headers, copy the values from `render.yaml`.

## Connecting it to the backend
1. Website `NEXT_PUBLIC_API_BASE_URL` = backend address; deploy.
2. Backend `CORS_ORIGINS` = `https://mckinley-frontend.onrender.com` exactly (no trailing slash, https only; the
   backend refuses to start with a wildcard, localhost or http origin); redeploy the backend.
3. Check: a preflight from the website origin gets `access-control-allow-origin` back; any other origin gets none.

## End-to-end checklist (Render website → Render backend → Supabase → OpenRouter)
1. **Supabase (dev project, synthetic data only).** `DATABASE_URL` = Session pooler URI (port 5432, IPv4). From a
   machine with that URL in `backend/.env`: `uv run alembic upgrade head` (Render also runs it on every start) and
   `uv run python -m app.seed_synthetic` (refuses any workbook not marked synthetic; replaces reference rows only).
2. **Backend** (see [render.md](render.md)): set `OPENROUTER_API_KEY` and `DATABASE_URL` in the Render Dashboard
   (Environment page, never in chat or git). `STAFF_API_TOKEN` is generated by Render.
3. **Health.** `GET /api/health` → `app_env: hosted`, `provider: openrouter`, `provider_ready: true`,
   `is_mock: false`, `demo_personas_enabled: false`. (Database and resident counts are hidden from the public;
   the startup log says `resident data loaded from the database (20 residents …)`.)
4. **Website.** Deploy with `NEXT_PUBLIC_API_BASE_URL`; set backend `CORS_ORIGINS`.
5. **Live checks** on the public URLs (phone and desktop): a question, a follow-up that needs the earlier turn, a
   tour request with a correction → Send → reference shown, "what's the status of my tour request?", refresh keeps
   the conversation, offline message shows "not sent" + retry, `/staff/` shows no records to the public, a persona
   request gets 403.

## Limits
- **Free backend sleeps** after ~15 minutes idle; the first visit then shows "Waking the assistant up…" for up to a
  minute. The free OpenRouter model took **10–55 s per reply** in testing (2026-11-11) and is rate-limited; busy
  periods show "The assistant is busy right now" with a retry.
- Free static sites include a monthly bandwidth allowance and build minutes; check the Render billing page.
- The public site is **guest-only** (no sign-in exists): see [../DEPLOYMENT_READINESS.md](../DEPLOYMENT_READINESS.md).
